Design decisions & rationale
  • Design system: Tailwind + Radix (or shadcn) for speed, accessibility and consistent tokens. Minimal, whitespace-focused card metaphors to match ChatGPT/Gemini/Claude aesthetic.
  • Calendar-first model: All booking flows write to a single shared calendar so the public booking page always reflects true availability. Free/busy only publishing preserves privacy.
  • MCP Developer-mode: Expose fine-grained tools (Calendar.*, Gmail.*, LinkedIn.*, Profile.*, Dashboard.generate_image). ReadOnlyHint and approval gates for all writes to prevent destructive automation without explicit approval.
  • Security: Short-lived access tokens, refresh rotation, secrets in Secret Manager, HMAC verification for webhooks, and RBAC + MFA for admin operations.
Integration summary (key actions)
  1. Auth: Google OAuth (calendar + gmail scopes), LinkedIn OAuth, and social platform OAuths. Store refresh tokens encrypted.
  2. Calendar: Use freebusy.query to show limited availability; create events on booking; watch for push notifications via Cloud Pub/Sub for sync.
  3. Gmail: users.watch → Pub/Sub → backend processing; templates for confirmations and triage rules.
  4. Profile & Socials: Aggregate LinkedIn, Twitter/X & Instagram profile summary for About page; queue/schedule posts with approval workflow.
  5. OpenAI/ChatGPT: Developer mode MCP to expose tools and a dashboard image generator; Code Interpreter used for chart generation and asset exports.
Production readiness & deployment decisions
Cloud Run / FastAPI | Postgres | Secret Manager | Pub/Sub

Key operational choices: FastAPI backend with OAuth handlers, Postgres + encrypted token store, Pub/Sub push handlers for Gmail/Calendar watches, and a React + Tailwind front end (Next.js for SEO). Use VPC Service Controls and private subnets for production. Write flows gated via MCP approvals.

Monitoring & SLOs: Instrument token refresh success, queue lengths, calendar create failures, and posting failures. Alert on token refresh error rate > 1% and booking failures > 0.5%.

Next steps to ship: create Google Cloud project, register OAuth consent, complete MCP app definitions and deploy backend to Cloud Run with CI/CD, then implement front end booking page and embed dashboard.

Developer-Mode (MCP) Tools

Expose these tools with JSON schema and readOnlyHint; require approval for write tools.

Calendar.list_freebusy (readOnly)
Calendar.create_event (write; approval)
Gmail.send (write; approval)
LinkedIn.post_share (write; approval)
Profile.get_about_me (readOnly)
Dashboard.generate_image (readOnly)
All write operations require approval in Developer Mode to prevent accidental mass writes.
